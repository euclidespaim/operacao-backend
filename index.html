Bem-vindos à Matrix: O que é o Backend?

⏱ 15 Minutos

Enquanto o Frontend roda diretamente no dispositivo do usuário (construindo a interface visual e capturando interações), o Backend processa a lógica de negócios, gerencia permissões e lê/escreve dados em um repositório centralizado de forma segura.

📁

Anatomia do HTTP

A comunicação Cliente-Servidor ocorre via protocolo HTTP. Toda requisição possui:
• Método (Verbo): Ação solicitada (GET, POST, PUT, DELETE).
• URL/Endpoint: O caminho do recurso.
• Headers: Metadados (ex: tipo de dados enviado).
• Body (Payload): Os dados enviados em formato JSON.

🖧

Códigos de Status (HTTP)

O servidor responde com códigos padronizados:
• 200 OK / 201 Created: Operação bem sucedida.
• 400 Bad Request: Erro na estrutura enviada.
• 404 Not Found: O endpoint não existe.
• 500 Internal Error: Falha no processamento do servidor.

🛡

Mecanismo de CORS

Cross-Origin Resource Sharing é uma barreira de segurança. O navegador impede que uma página em uma origem (ex: seu site de aulas) faça requisições automáticas a outra origem (ex: seu servidor local) sem permissão. O json-server libera isso definindo headers especiais.

Subindo seu Primeiro Servidor

⏱ 15 Minutos

Usaremos o json-server como nossa ferramenta local para simular um servidor real e um banco de dados relacional a partir de um arquivo JSON. Siga as etapas abaixo no VS Code de sua máquina:

01

Criar Diretório de Trabalho VS Code

Crie uma pasta em sua Área de Trabalho chamada missao-backend.
Abra o VS Code, clique em File > Open Folder e selecione a pasta criada.

02

O Arquivo de Banco de Dados VS Code

No VS Code, crie um arquivo chamado db.json, insira o seguinte conteúdo e salve:

JSON (db.json) 
{
  "agentes": [
    { "id": "1", "nome": "Neo", "status": "Ativo" },
    { "id": "2", "nome": "Trinity", "status": "Oculto" }
  ]
}
03

Inicialização do Servidor VS Code

Abra o terminal integrado do VS Code (Ctrl + ') e execute o comando abaixo para iniciar o listener do servidor:

Terminal 
npx json-server@0.17.4 db.json
ℹ️
Por que especificar a versão @0.17.4? A versão mais recente (v1.x) do json-server ignora o ID enviado na requisição POST e gera um ID aleatório alfanumérico (ex: lh7K8) para evitar conflitos de dados. Usando a versão estável @0.17.4, o servidor respeitará exatamente os IDs que enviarmos (ID 3 para Morpheus).

Operações CRUD na API

⏱ 25 Minutos

Abaixo estão os scripts para realizar as quatro operações básicas do banco de dados (CRUD). Copie e execute-os no Console do Navegador (F12) desta página para manipular a sua API local em execução.

R

1. Leitura (GET) Navegador (F12)

Lista os dados contidos no servidor local.

JavaScript (Console F12) 
fetch('http://localhost:3000/agentes')
  .then(resposta => resposta.json())
  .then(dados => console.log("Agentes lidos:", dados));
C

2. Criação (POST) Navegador (F12)

Insere um novo agente. O servidor atribui o ID e persiste o novo registro em db.json.

JavaScript (Console F12) 
fetch('http://localhost:3000/agentes', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ id: "3", nome: "Morpheus", status: "Procurado" })
})
.then(resposta => resposta.json())
.then(dados => console.log("Agente criado:", dados));
U

3. Atualização (PUT) Navegador (F12)

Substitui ou atualiza um registro existente identificando-o pelo ID na URL (ex: atualizando status da Trinity no ID 2).

JavaScript (Console F12)

  method: 'PUT',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ nome: "Trinity", status: "Ativo" })
})
.then(resposta => resposta.json())
.then(dados => console.log("Agente atualizado:", dados));
D

4. Exclusão (DELETE) Navegador (F12)

Remove um registro permanentemente passando o ID do elemento correspondente na URL.

JavaScript (Console F12) 
fetch('http://localhost:3000/agentes/3', {
  method: 'DELETE'
})
.then(resposta => console.log("Status da exclusão:", resposta.status));

02

O Script de Integração (JavaScript) VS Code

No seu arquivo app.js local, implemente as funções de comunicação com o servidor e manipulação de DOM (innerHTML) para injetar os dados dinamicamente no HTML do seu navegador:

JavaScript (app.js) 
const urlBase = 'http://localhost:3000/agentes';

// 1. Função de Leitura (GET): Carrega os agentes e desenha na tela
function buscarAgentes() {
  fetch(urlBase)
    .then(resposta => {
      if (!resposta.ok) throw new Error(`Erro: ${resposta.status}`);
      return resposta.json();
    })
    .then(dados => {
      const lista = document.getElementById('lista-agentes');
      lista.innerHTML = ''; // Limpa a lista antes de renderizar
      
      dados.forEach(agente => {
        const item = document.createElement('li');
        item.innerHTML = `
          [ID ${agente.id}] ${agente.nome} - ${agente.status}
        `;
        lista.appendChild(item);
      });
    })
    .catch(erro => console.error("Falha ao buscar:", erro.message));
}

// 2. Função de Criação/Edição (POST/PUT): Cria se não existe, atualiza se existe
async function salvarAgente() {
  const id = document.getElementById('agente-id').value.trim();
  const nome = document.getElementById('agente-nome').value.trim();
  const status = document.getElementById('agente-status').value;

  if (!id) return alert('O ID é obrigatório!');

  try {
    // Verifica primeiro se o ID já existe
    const checkRes = await fetch(`${urlBase}/${id}`);
    const existe = checkRes.ok; // se status for 200 (ok), o registro existe

    const url = existe ? `${urlBase}/${id}` : urlBase;
    const metodo = existe ? 'PUT' : 'POST';
    
    const res = await fetch(url, {
      method: metodo,
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ id, nome, status })
    });

    if (!res.ok) throw new Error(`Erro: ${res.status}`);
    
    alert(existe ? 'Agente atualizado com sucesso!' : 'Agente criado com sucesso!');
    buscarAgentes(); // Atualiza a lista na tela
  } catch(erro) {
    console.error("Falha ao salvar:", erro.message);
  }
}

// 3. Função de Exclusão (DELETE): Exclui do banco pelo ID
function excluirAgente() {
  const id = document.getElementById('agente-id').value.trim();
  if (!id) return alert('Digite o ID do agente para excluí-lo.');

  fetch(`${urlBase}/${id}`, {
    method: 'DELETE'
  })
  .then(resposta => {
    if (!resposta.ok) throw new Error(`Erro: ${resposta.status}`);
    alert('Agente deletado do sistema!');
    buscarAgentes(); // Recarrega a lista na tela
  })
  .catch(erro => console.error("Falha ao excluir:", erro.message));
}

// Carrega os dados automaticamente assim que a página terminar de carregar
window.onload = buscarAgentes;

Sincronização e Salvamento

⏱ 15 Minutos

Agora que o sistema está em pleno funcionamento e integrado, vamos configurar as exclusões do Live Server para não causar loops de carregamento indesejados e salvar nosso código na nuvem.

01

Evitar Auto-Recarregamentos do Live Server VS Code

Por padrão, se você estiver usando a extensão Live Server do VS Code, a sua página do navegador irá recarregar automaticamente toda vez que você cadastrar, alterar ou deletar um agente (porque a mudança altera o arquivo db.json e o Live Server assume que um arquivo de código foi alterado).

Para corrigir isso, adicione a configuração abaixo nas configurações globais do VS Code (Arquivo > Preferências > Configurações > procure por "ignore files" no Live Server), ou crie uma pasta chamada .vscode na raiz do projeto com um arquivo settings.json contendo:

JSON (.vscode/settings.json) 
{
  "liveServer.settings.ignoreFiles": [
    "**/db.json"
  ]
}
