Módulo 1.1 // Fundamentos Teóricos Navegador

Bem-vindos à Matrix: O que é o Backend?

⏱ 15 Minutos

Enquanto o Frontend roda diretamente no dispositivo do usuário (construindo a interface visual e capturando interações), o Backend processa a lógica de negócios, gerencia permissões e lê/escreve dados em um repositório centralizado de forma segura.

📁

Anatomia do HTTP

A comunicação Cliente-Servidor ocorre via protocolo HTTP. Toda requisição possui:
• Método (Verbo): Ação solicitada (GET, POST, PUT, DELETE).
• URL/Endpoint: O caminho do recurso.
• Headers: Metadados (ex: tipo de dados enviado).
• Body (Payload): Os dados enviados em formato JSON.

🖧

Códigos de Status (HTTP)

O servidor responde com códigos padronizados:
• 200 OK / 201 Created: Operação bem sucedida.
• 400 Bad Request: Erro na estrutura enviada.
• 404 Not Found: O endpoint não existe.
• 500 Internal Error: Falha no processamento do servidor.

🛡

Mecanismo de CORS

Cross-Origin Resource Sharing é uma barreira de segurança. O navegador impede que uma página em uma origem (ex: seu site de aulas) faça requisições automáticas a outra origem (ex: seu servidor local) sem permissão. O json-server libera isso definindo headers especiais.

📖 Dicionário de Verbos HTTP (Métodos)

Os métodos HTTP indicam a ação semântica que o cliente deseja realizar no servidor. Mantemos a ordem do acrônimo CRUD para operações principais, seguidos de outros métodos auxiliares e metadados:

POST [C]reate de CRUD

Lógica: Criação de Recurso

Envia dados no corpo (body) da requisição para criar um novo registro no servidor. Geralmente resulta em um status 201 Created. Não é um método idempotente (fazer a mesma chamada várias vezes criará vários registros duplicados).

Quando Usar: Ao cadastrar um novo usuário, enviar um formulário de contato ou realizar um novo post em um blog.
GET [R]ead de CRUD

Lógica: Leitura e Recuperação

Solicita a representação de um recurso específico. Requisições utilizando GET devem apenas retornar dados e não devem ter efeitos colaterais de modificação. É seguro e idempotente.

Quando Usar: Ao pesquisar uma lista de agentes, carregar um feed de notícias ou abrir a página de perfil de um usuário.
PUT [U]pdate de CRUD

Lógica: Substituição Completa

Substitui todas as representações atuais do recurso de destino pelos dados enviados no corpo (payload). Se o recurso não existir, pode criá-lo (dependendo da lógica da API). É idempotente (enviar a mesma requisição PUT repetidamente deixa o recurso no mesmo estado).

Quando Usar: Para atualizar o registro inteiro de um agente (enviando nome, status, data de cadastro de uma vez para substituir o antigo).
DELETE [D]elete de CRUD

Lógica: Exclusão de Recurso

Remove o recurso especificado no endpoint (ex: /agentes/3). É um método idempotente (tentar excluir o recurso após ele já ter sido deletado não mudará o estado do banco, embora o status de retorno possa mudar de 200/204 para 404).

Quando Usar: Ao apagar uma conta de usuário, remover um agente inativo do banco de dados ou cancelar uma inscrição.
PATCH Modificador Auxiliar

Lógica: Modificação Parcial

Aplica modificações parciais a um recurso. Ao contrário do PUT que exige o envio de todo o objeto para sobrescrevê-lo, o PATCH permite enviar apenas os atributos específicos que devem ser alterados.

Quando Usar: Para atualizar apenas o status de um agente (ex: mudar de 'Oculto' para 'Ativo') sem alterar nem reenviar o nome dele.
HEAD Modificador Auxiliar

Lógica: Apenas Cabeçalhos (Headers)

Solicita uma resposta idêntica à de uma requisição GET, porém **sem o corpo de resposta** (body). Ele retorna apenas os headers (metadados). É extremamente leve e rápido.

Quando Usar: Para verificar se um arquivo grande mudou (verificando o header `Last-Modified` ou `Content-Length`) antes de baixá-lo ou checar se um link/URL está ativo sem puxar o HTML.
OPTIONS Metadados / Segurança

Lógica: Opções de Comunicação

Retorna quais métodos HTTP e cabeçalhos são permitidos para o recurso de destino. É o método de segurança utilizado pelo mecanismo de CORS do navegador para fazer as requisições "preflight" (pré-voo) antes de enviar chamadas de escrita/modificação reais.

Quando Usar: Usado de forma automática pelo navegador (ou manualmente para depuração) para inspecionar quais métodos a API suporta (ex: checar se a API aceita DELETE ou PUT).
TRACE Diagnóstico / Loopback

Lógica: Loopback de Teste

Realiza um teste de loopback de mensagem ao longo do caminho para o recurso de destino. O servidor retorna exatamente a requisição recebida (incluindo cabeçalhos) de volta para o cliente no corpo da resposta.

Quando Usar: Para depuração e diagnóstico de rede, permitindo verificar se servidores proxy intermediários, firewalls ou balanceadores de carga modificaram seus cabeçalhos originais de requisição.
CONNECT Túnel de Rede

Lógica: Túnel TCP/IP

Estabelece um túnel de comunicação direta bidirecional com o servidor identificado pelo recurso de destino. Ele é usado principalmente para redirecionar conexões TCP brutas de maneira transparente através de proxies HTTP.

Quando Usar: Utilizado automaticamente por navegadores e servidores proxy para estabelecer uma conexão criptografada segura via SSL/TLS (túnel HTTPS) ao se comunicar com sites seguros.

Aviso de Segurança: Bloqueio de CORS na Vercel (HTTPS para HTTP Localhost)

Se você está acessando este painel hospedado na Vercel (via HTTPS), o navegador pode bloquear as chamadas de rede para a sua API rodando em localhost (via HTTP) devido às políticas de Private Network Access (PNA) do Google Chrome e políticas de Conteúdo Misto (Mixed Content).

Como Resolver (Escolha uma opção):
  • Opção A (Recomendada - Sem Código): Desative temporariamente a barreira do navegador. Abra uma nova aba no Chrome, acesse chrome://flags/#block-insecure-private-network-requests, mude para Disabled e reinicie o navegador.
  • Opção B (Via Código do json-server): Crie um arquivo chamado cors-fix.js na mesma pasta de db.json com o conteúdo:
    module.exports = (req, res, next) => {
  res.header('Access-Control-Allow-Private-Network', 'true');
  res.header('Access-Control-Allow-Origin', '*');
  next();
};
    E inicialize o json-server especificando a versão @0.17.4 com o comando:
    npx json-server@0.17.4 db.json --middlewares cors-fix.js
    ⚠️ Nota: A versão padrão mais recente (json-server v1.0.0+) removeu a opção --middlewares, causando erros de "unknown option". Usar a versão @0.17.4 é obrigatório para esse parâmetro funcionar.

Ler apenas cabeçalhos (HEAD) Navegador (F12)

JavaScript

02

O Motor (JavaScript) VS Code

No seu app.js, adicione as funções de fetch e inserção no DOM (innerHTML):

JavaScript
const urlBase = 'http://localhost:3000/agentes';

function buscarAgentes() {
  fetch(urlBase)
    .then(res => res.json())
    .then(dados => {
      const lista = document.getElementById('lista-agentes');
      lista.innerHTML = '';
      dados.forEach(ag => {
        const li = document.createElement('li');
        li.innerHTML = `[ID ${ag.id}] ${ag.nome} - ${ag.status}`;
        lista.appendChild(li);
      });
    });
}

async function salvarAgente() {
  const id = document.getElementById('agente-id').value.trim();
  const nome = document.getElementById('agente-nome').value.trim();
  const status = document.getElementById('agente-status').value;
  if (!id) return alert('ID é obrigatório!');
  
  const existe = (await fetch(`${urlBase}/${id}`)).ok;
  const url = existe ? `${urlBase}/${id}` : urlBase;
  
  fetch(url, {
    method: existe ? 'PUT' : 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ id, nome, status })
  }).then(() => buscarAgentes());
}

async function alterarStatusParcial() {
  const id = document.getElementById('agente-id').value.trim();
  const status = document.getElementById('agente-status').value;
  if(!id) return alert('Digite o ID para o PATCH');
  
  fetch(`${urlBase}/${id}`, {
    method: 'PATCH',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ status })
  }).then(() => buscarAgentes());
}

function excluirAgente() {
  const id = document.getElementById('agente-id').value.trim();
  if(!id) return alert('Digite o ID');
  fetch(`${urlBase}/${id}`, { method: 'DELETE' }).then(() => buscarAgentes());
}

window.onload = buscarAgentes;

Promises e Event Loop

⏱ 15 Minutos

O JavaScript executa códigos de forma single-threaded (síncrona). Chamadas externas ao servidor demoram para responder. Para que a interface não congele, o navegador delega essas tarefas em segundo plano e retorna o resultado em um contêiner chamado Promise.

⏳

Event Loop

As tarefas pesadas como fetch() são empurradas para a Web APIs do navegador. O loop de eventos monitora a fila de retorno (*Callback Queue*) e injeta as respostas na pilha de execução principal (*Call Stack*) assim que ela fica vazia.

📦

Estados de uma Promise

Toda Promise assume três estados possíveis:
• Pending: Resposta ainda em processamento.
• Fulfilled: Sucesso. Retorna dados úteis com .then().
• Rejected: Erro. Captura o motivo da queda no bloco .catch().

Módulo 2.2 // Nova Sintaxe VS Code

Refatorando com Async / Await

⏱ 15 Minutos

A sintaxe de async e await é um açucar sintático (*syntactic sugar*) criado sobre as Promises. Ela simplifica o fluxo de escrita assíncrona, fazendo com que o código pareça síncrono e linear, eliminando a dependência do encadeamento recursivo de múltiplos .then().

1

A palavra-chave async VS Code

Toda função que precisa pausar e aguardar uma chamada externa deve ser marcada com o modificador async antes de sua assinatura. Isso garante que a função retorne automaticamente uma Promise.

2

A palavra-chave await VS Code

Colocada antes do fetch(), a instrução await instrui o JavaScript a pausar a execução daquela função até que a Promise mude de estado, devolvendo o valor da resposta imediatamente.

JavaScript
// Antes: com .then
function buscar() {
  fetch('http://localhost:3000/agentes')
    .then(res => res.json())
    .then(dados => console.log(dados));
}

// Depois: com async/await
async function buscar() {
  const resposta = await fetch('http://localhost:3000/agentes');
  const dados = await resposta.json();
  console.log(dados);
}

Módulo 2.3 // Tratamento de Falhas VS Code

Try/Catch e Resiliência

⏱ 20 Minutos

Ao usar async/await, não temos mais a função `.catch()` atrelada ao fluxo da Promise. Capturamos falhas de rede de forma estruturada englobando as instruções em blocos de exceção padrão: try/catch.

01

Estrutura de Captura VS Code

Se o servidor cair ou a conexão for perdida durante o await fetch(), a execução desvia imediatamente para o bloco do catch:

JavaScript
async function buscarAgentes() {
  try {
    const res = await fetch('http://localhost:3000/agentes');
    
    // fetch resolve em erros HTTP comuns (ex: 404), logo devemos validar res.ok:
    if (!res.ok) {
      throw new Error(`Servidor respondeu com código ${res.status}`);
    }
    
    const dados = await res.json();
    console.log("Sucesso:", dados);
  } catch (erro) {
    // Captura erros de rede OU o erro lançado manualmente acima
    console.error("Operação Backend falhou:", erro.message);
  }
}

Módulo 2.4 // Sanitização VS Code

Validação do Payload (Payload Validation)

⏱ 25 Minutos

A regra de ouro do Backend é: **nunca confie no cliente**. Antes de disparar requisições do tipo POST ou PUT, devemos sanitizar e validar os dados de formulários no JavaScript Frontend para impedir tráfego desnecessário de payloads defeituosos.

01

Validação Local no Cliente VS Code

Refatore seu arquivo app.js local para incorporar validações lógicas nas funções de gravação:

JavaScript (app.js)
async function salvarAgente() {
  const id = document.getElementById('agente-id').value.trim();
  const nome = document.getElementById('agente-nome').value.trim();
  const status = document.getElementById('agente-status').value;

  // 1. Impedir envio de campos vazios ou formatos inválidos
  if (!id || isNaN(id)) {
    return alert('O ID é obrigatório e precisa ser um número!');
  }
  if (nome.length < 3) {
    return alert('O nome do agente precisa ter ao menos 3 caracteres!');
  }

  try {
    const checkRes = await fetch(`http://localhost:3000/agentes/${id}`);
    const existe = checkRes.ok;

    const res = await fetch(existe ? `http://localhost:3000/agentes/${id}` : 'http://localhost:3000/agentes', {
      method: existe ? 'PUT' : 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ id, nome, status })
    });

    if (!res.ok) throw new Error(`Status HTTP: ${res.status}`);
    alert('Operação persistida!');
    buscarAgentes();
  } catch(erro) {
    alert('Erro ao enviar: ' + erro.message);
  }
}

Módulo 3.1 // Parâmetros de URL Navegador

Query Parameters (Filtros de URL)

⏱ 15 Minutos

Para buscar dados filtrados sem sobrecarregar o cliente, utilizamos Query Parameters na URL. Eles começam com `?` e se estruturam como chave-valor `chave=valor` separados por `&`.

🔍

Filtragem Direta

endpoints locais como o `json-server` aceitam filtros direto na URL. Exemplo:
http://localhost:3000/agentes?status=Ativo
Isso instrui o banco de dados a retornar apenas os agentes com status "Ativo".

📊

Ordenação e Limites

Podemos usar parâmetros especiais para formatar a resposta do servidor:
• ?_sort=nome (ordena por nome)

Pesquisa e Filtragem em Tempo Real

⏱ 20 Minutos

Vamos escrever a função de busca parametrizada no JavaScript, convertendo as opções do formulário em Query Parameters dinâmicos e atualizando a interface utilizando `.map()`.

01

Implementação do Script VS Code

Escreva a função filtrarAgentes() no seu arquivo app.js local:

JavaScript (app.js)
async function filtrarAgentes() {
  const nome = document.getElementById('busca-nome').value.trim();
  const status = document.getElementById('busca-status').value;

  // 1. Montar a URL dinâmica usando Query Parameters
  let url = 'http://localhost:3000/agentes?';
  
  if (nome) {
    url += `nome_like=${nome}&`; // Filtra nomes parciais (contém)
  }
  if (status) {
    url += `status=${status}&`;  // Filtra por status exato
  }

  try {
    const res = await fetch(url);
    if (!res.ok) throw new Error();
    const dados = await res.json();
    
    // 2. Renderizar lista usando .map()
    const lista = document.getElementById('lista-agentes');
    lista.innerHTML = dados.map(ag => {
      return `<li>[ID ${ag.id}] ${ag.nome} - <em>${ag.status}</em></li>`;
    }).join('');
    
  } catch(erro) {
    console.error("Falha ao filtrar:", erro.message);
  }
}

async function lerBanco() {

PUT e DELETE Manuais

⏱ 20 Minutos

Para completar o CRUD manual, implementaremos as rotas PUT (atualização) e DELETE (remoção) usando filtros lógicos de manipulação de array no JavaScript.

01

Criando as rotas PUT e DELETE no Servidor VS Code

Insira os blocos das rotas no seu arquivo server.js local:

JavaScript (server.js PUT/DELETE)
// Rota de atualização (PUT)
app.put('/agentes/:id', async (req, res) => {
  const { id } = req.params;
  try {
    const banco = await lerBanco();
    const index = banco.agentes.findIndex(ag => ag.id === id);
    
    if (index === -1) {
      return res.status(404).json({ erro: "Agente não encontrado" });
    }
    
    // Atualiza apenas os campos enviados no body
    banco.agentes[index] = { ...banco.agentes[index], ...req.body };
    await salvarBanco(banco);
    
    res.json(banco.agentes[index]);
  } catch (erro) {
    res.status(500).json({ erro: "Erro ao atualizar agente" });
  }
});

// Rota de exclusão (DELETE)
app.delete('/agentes/:id', async (req, res) => {
  const { id } = req.params;
  try {
    const banco = await lerBanco();
    const filtrados = banco.agentes.filter(ag => ag.id !== id);
    
    if (banco.agentes.length === filtrados.length) {
      return res.status(404).json({ erro: "Agente não encontrado" });
    }
    
    banco.agentes = filtrados;
    await salvarBanco(banco);
    
    res.status(200).json({ msg: "Excluído com sucesso" });
  } catch (erro) {
    res.status(500).json({ erro: "Erro ao excluir agente" });
  }
});
